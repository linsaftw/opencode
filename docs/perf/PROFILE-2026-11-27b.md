## Proposed fixes (top 3)
1. `_prepare`, packages/core/src/database/drizzle/sqlite-core/effect/select.ts:221-231: cache the compiled query (sql string + field order)
   on the builder when the select is reused via `.prepare()` (lines 251-252); for one-time queries, hoist `orderSelectedFields` out of the hot path.
   Expected: removes most of the 12.5% for repeated selects. Needs a test that results are unchanged on the same DB.
2. Effect callback wrapper, node_modules/@effect/platform-node-shared/dist/internal/utils.js:3 (16.9%): find which caller uses `Effect.async`/
   fs callbacks per request (writeAll is 0.7%, so likely per-query Effect.tryPromise in the sqlite client). Fix at the sqlite client boundary:
   batch the synchronous `values()`/`all()` calls into one `Effect.sync` instead of one async wrapper per query. Verify with a fresh profile.
3. `runLoop`, effect/dist/internal/effect.js:453 (13.0%): fewer fiber hops per query. Same fix as (2): fewer `yield*` boundaries in the
   per-message write path (projector and session prompt loop). Measure before/after with the same 40-conversation driver.
