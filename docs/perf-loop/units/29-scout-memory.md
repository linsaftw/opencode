## Findings

1. **Per-session WebSocket state survives every completed turn** — `packages/core/src/session/model-transport.ts:132` (`const states = new Map<SessionSchema.ID, State>()`), entry created in `bind`/`state` at `:133-139`, released only by `close` (`:537-544`, called from `Session.remove` at `packages/core/src/session.ts:371` and the move/closed-Location paths at `packages/core/src/session/runner/llm.ts:79,99`), by `closeAll` on layer shutdown (`:545-557`), or by the layer finalizer. Key: Session ID. After a normal turn the entry keeps `State.channel` (open `WebSocketConnection`, message reader fiber, `checkpoint`, possibly `pending`), because `completed`/`incomplete` terminals keep the socket for reuse (`:430-445`). A finished, never-deleted Session therefore retains a live provider socket and its buffers until the process exits or the Session is explicitly deleted. Estimated size per session: one TLS socket + read buffers + channel/checkpoint state (tens of KB plus a file descriptor; server-side counterpart also retained). Release/bound fix: mirror the existing 55-minute rotation rule — sweep `states` and `close`/delete owners whose `channel` is idle (no `active`, no `pending`) and older than `ROTATE_AFTER_MS`; the next request reconnects exactly as rotation already does, so behavior is unchanged. Risk of fix: low. Likelihood of growth: certain (all sessions that stream). Rating: **high**.

2. **Per-session environment variables are retained for the life of the process** — `packages/core/src/session/environment.ts:18` (`environments = new Map<SessionSchema.ID, Variables>()`), written by `set` (`:22-25`, reached from `packages/server/src/handlers/session.ts:220`), deleted only by `Session.remove` (`packages/core/src/session.ts:375`). Keys are Session IDs; sessions are normally never removed, so the map grows monotonically with every Session that ever had variables set. Estimated size per session: small (a shallow copy of a string record, typically < 1 KB), but unbounded in count. Minimal safe fix: make this a bounded cache (e.g. LRU/`Cache` with a cap) or clear the entry when the Session's execution goes idle, since variables are re-sent by the client/handler when needed; alternatively key an ephemeral `WeakMap`-like store on the loaded Session object. Risk: low (need to confirm callers re-set variables per use). Rating: **medium-low**.

3. **Warming state and a sleeping fiber outlive their Session** — `packages/core/src/plugin/warming.ts:30` (`sessions = new Map<Session.ID, {last, expires, settings}>`), inserted at `:90`, removed only at expiry inside the loop (`:42-44`) or when config disappears (`:66`); deleting a Session does not notify this map. Each entry also owns a forked loop fiber (`:95-100`) that can wake and call `ctx.session.generate` for an already-deleted Session before the (default 30 minute) `duration` elapses. Estimated size per session: tiny map entry plus one parked fiber; count is bounded by Sessions active in the last `duration`, but stale entries still trigger useless work. Minimal safe fix: subscribe to `SessionEvent.Deleted` (or Location shutdown) and delete the key plus interrupt the loop fiber; keep the expiry as a backstop. Risk: low. Rating: **low-medium**.

4. **Module-level provider discovery caches are never evicted by key** — `packages/core/src/plugin/provider/ollama.ts:42` (`const shows = new Map<string, ShowCache>()`, keyed by `client.root` URL, overwritten at `:54,74` but never deleted), and `packages/core/src/plugin/provider/local.ts:34` (`const discovery = new Map<string, {checked, apiKey?, models?}>()`, keyed by endpoint root, set at `:105,111`, never deleted). Entries hold full model metadata (`/api/show` responses with `model_info`, templates, etc. for Ollama; entire discovered model arrays for local providers). Growth is bounded by the number of distinct endpoints ever configured, but a removed or reconfigured endpoint keeps its last payload for the process lifetime. Estimated size: from a few KB to hundreds of KB per endpoint depending on model count. Minimal safe fix: on each discovery, delete keys no longer present in the configured endpoint set (or cap entries), leaving current behavior for live endpoints. Risk: low. Rating: **low**.

5. **Plugin update/status bookkeeping is never pruned for removed targets** — `packages/core/src/plugin/update.ts:31` (`status = new Map<string, {outdated, checkedAt}>()`; set at `:45`, deleted only after a successful `update` at `:58`), and `packages/core/src/plugin/module.ts:25` (`watched = new Set<string>()` of watched plugin entry paths; never removed when a plugin is uninstalled or a generation is dropped). Keys are plugin package targets / absolute plugin file paths, so repeated install/remove or config churn accumulates stale strings and metadata for the process lifetime. Estimated size per entry: tiny; count is bounded by historical config, not by live plugins. Minimal safe fix: on each supervisor activation, drop `status`/`watched` keys not present in the current target set. Risk: low. Rating: **low**.

6. **Cycle-1 per-message memos: none present; nothing to bound** — `packages/core/src/session/model-request.ts` has no module- or layer-level message memo: the only maps are per-call temporaries inside `prepare` (`:251` `given`, `:271` `byName`, `:272` `hooked`) and are dropped when the prepared request returns. `packages/core/src/session/projector.ts` likewise has no per-message cache or memo map; its `bus.project` registrations (`:447-729`) are global projector closures, not per-message state. The only WeakMaps on these paths are genuinely keyed by live objects (`packages/core/src/bus.ts:207` routes, `packages/core/src/provider.ts:326` model definitions), so they are GC-safe. No release/bound change is needed; if a memo was expected here it is not in this checkout. Rating: **none (verified clean)**.
